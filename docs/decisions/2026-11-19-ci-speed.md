# CI speed: the unit tests in two shards, the fish fresh players side by side

Date: 2026-11-19. PR: #1177. Rules or docs touched: W14, W24 (unchanged); ROADMAP "CI speed, what is left";
docs/spec/deploy.md "Tests"; docs/PAGES.md.

## Context

The ROADMAP row "CI speed, what is left" named the two longest parts of a PR's CI: Checks' unit tests and the fish
fresh smoke. On the 10 runs before this PR, the Checks job took 219 s (median; 189-305), 172 s of it the unit tests, and
`smoke (fish fresh)` took 213 s (162-256). On CI the unit-test files already ran three at once (`node --test` on a
4-core runner; `tests/slot.js` is a no-op there), so the only gain left was more runners. The fish fresh group plays
five brand-new players one after the other, one per seed of `Math.random`; a local measure showed about 97% of each
player's time is its checks inside the page (15 questions, then the draws on every circle-1 entry), not the page load.

## Decision

Integrator's call (CI layout, an implementation detail; easy to correct):
- Checks keeps its `checks` job for everything but the unit tests, and a `unit` job runs them in two shards on two
  runners (`node --test --test-shard=k/2 tests/*.test.js`), so every file still runs on every PR and train.
  `tests/smokeparts.test.js` fails when the shard list is not 1 to n or another `node --test` run comes back.
- The fish fresh players play side by side, each in its own browser context: all five at once on CI, two at a time
  on a shared machine (the two cores of the smoke's slot). The seeds, the question count and the draw counts stay as
  they are.
- Two shards rather than three: Checks is no longer the longest workflow, and each job more adds to the queue when
  runs overlap (runs already waited up to 88 s for a runner).

No test was dropped, skipped or weakened, and no `slow` tag was added (that question, Q414, is still open for Pierre).

## Consequences

On #1177's run (one sample): Checks 167 s from start to end (`checks` 35 s, `unit tests` 112 s and 162 s), against a
226 s median before; `smoke (fish fresh)` 104 s; Smokes 231 s against 267 s. The two shards together ran 2107 tests,
all passing. The heavy `analysis*` files fall in the same shard, so the shards are uneven; `smoke (admin 1280 more)`
is now the longest job. Both are in the ROADMAP row. `tools/train.py` needs no change: it waits for the workflows by
name (Checks, Smokes) and reads every check on a PR's head.
