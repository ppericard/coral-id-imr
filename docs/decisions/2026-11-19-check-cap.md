# The check tools stop at 40 minutes, and level 3 waits for Pierre's go on a GitHub runner

Date: 2026-11-19. PR: #1274. Rules or docs touched: L11; docs/LEARNING.md "Validating a learning change" ("The cap",
"On a GitHub runner"); tools/README.md; `.github/workflows/learncheck.yml` (2026-11-20, below).

## Context

Rule L11 (Q405, 2026-11-18) caps every check at 40 minutes of compute and keeps level 3 off this machine; Q415
(2026-11-19) asked for the tools to be aligned with it. Until then `tools/learnsim.js` ran to the end whatever its size.

## Decision

Pierre, Q415 (2026-11-19, 06:50): «L11 fait foi sur 1, 3 et 4. Pour le 3, il faut aligner l'outil, avec une limite de
temps de 40 min et le feu vert. Pour 2, garder les chiffres de LEARNING comme minimum». Built in `tools/checkbudget.js`,
used by `tools/learnsim.js` in both worlds, `tools/learncmp.js` reading its mark:

- a wall-clock budget of 40 minutes, `--budget MIN` for less, never more; a plan from a short calibration run or
  `--per-job SEC`, refused over the budget with the options that fit; a stop at the budget that keeps the runs done and
  marks the output cut; a run cut before any job finished still writes its `--out` (the cut, no runs) and exits 3;
- the calibration is outside the stop, so a budget under 1 minute needs `--per-job` and a calibration that overruns
  marks the result cut;
- level 3 (over 20 seeds, or over 10,000 answers in the rated world) refused unless `--pierre-go "…"` (the reference of
  his go) is given on a GitHub runner; elsewhere the dispatch command is printed;
- level 2's defaults are not lowered: LEARNING.md's figures stay the minimum, and a check that does not fit is split.

Cut for scope (W27, after two Codex rounds): `.github/workflows/learncheck.yml` was left unchanged in #1274. A first
version gave it `pierre_go` and `budget` inputs and a `timeout` around each arm; Codex found that it gave each of its
four runs a fresh budget, checked the go only inside the newer checkout, and left an empty cut arm unread by `learncmp`
for some primaries. They were built next (2026-11-20, the ROADMAP row "learncheck.yml under the 40-minute cap"):
- one deadline, set before the first run, shared by the arms and worlds; each run gets the equal share of 40 minutes
  (10 with both worlds, 20 with one) or the `budget` input (minutes per run; `runs x budget` over 40 is refused), less
  where the deadline is nearer; `timeout` ends a run at its limit, never past the deadline, so an older `before` that
  ignores `--budget` is bounded too; a run that left no file gets a stub marked cut;
- the level-3 go (`pierre_go`) checked in the first step, before either checkout, from level 2's ceilings (constants
  equal to `checkbudget.js`, a test holds them); `args` cannot carry the options the workflow sets;
- `learncmp` reads no primary from an arm cut before any run finished, population primaries included (the guard sits
  before both primary branches), and says it was not read.
Integrator's calls, easy to change: `budget` is minutes per run (not per check); the job's limit is 90 minutes (was 360).

Integrator's calls, each easy to change: the 40 minutes hold on the runner too (a constant, `MAX_MIN`; the brief said
"never more than 40 on this machine"); the budget is per learnsim run, so a paired check is two runs; level 3 is
detected by size (the ceilings of level 2) rather than by a flag; the estimate is a straight line from a calibration run
of at most 1,000 answers or 100 questions; a cut run exits 0 with a banner (nothing done: exit 3); `--pierre-go` takes
any non-empty reference.

## Consequences

- A level-2 check that cannot reach LEARNING.md's seeds and length in 40 minutes is refused, with the options (fewer
  seeds, a shorter run, fewer profiles): the integrator splits it by world or by profile, never lowers the figures.
- A level-3 design (40 seeds of 30,000 answers) cannot fit one 40-minute run; it is split, or Pierre decides to lift the
  cap for it (one constant).
- A cut file keeps `cut` and `budgetMin`; `learncmp` prints the mark and compares the complete pairs.
- The Learning check workflow keeps the cap and the go itself (above); a default check of fish in both worlds, an hour,
  is now refused by the tool's plan or cut: it is split by world.
- No change to the app, the sheet or any player's progress.
