The self-update watches Google's 200-version limit (integrator's call, an operational safeguard after the 2026-11-22 incident: 200 versions kept, every `POST /versions` answered 429 for about 36 hours and the script stayed at v218 until old versions were deleted by hand). After each deploy the script counts the versions the project keeps (`GET /versions`, page by page; `SELF_VERSIONS`, `selfVersionsCount_`), and again every hour while the count is 170 or more, so a clean-up is seen without a deploy. From 170 it writes one line a day to the Alerts tab (the admin's To do > Alerts) and the Deploy log, with the count and what to do: delete old versions in the Apps Script editor (Project history), since the API cannot delete one. A 429 at `POST /versions` now reads in the Deploy log "error: version limit reached: delete old versions …" instead of Google's raw JSON (counted as 200; the update stays pending and finishes at the next run after the clean-up). While the count is 170 or more, the public stats reply carries it as `vers` (the app ignores it), and the hourly Health check names the limit (`tools/health.py`): a note near it, a failure at once at 200 while behind `main`.
