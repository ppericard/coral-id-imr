Look-alike account names (integrator's call, REE-35, 2026-11-23): two names that look the same can no longer be two accounts, and a name is never cut inside an emoji. A new account name (a save with no account yet, `doPost_`; an admin archive name, `users_` `userArchive`) is made NFC (`core.js` `nameClean`), refused when it holds an invisible character (`core.js` `nameHidden`: zero-width space, joiner and non-joiner, bidi controls, the other format characters of Unicode category Cf, Hangul fillers and the like; an emoji's own joiner and a flag's tags are allowed) and refused as taken when it looks like the name of an account in the RAs tab (`core.js` `nameSkeleton`: decomposed, invisible characters dropped, the Greek and Cyrillic letters Unicode's confusables data (UTS #39, v18.0.0) maps to one Latin letter mapped to it, NFKC, case aside, spaces folded; `nameIssue_`). A save is refused as `error: 'reserved'` with `why: 'invisible'|'lookalike'`, which every app already stops on; an archive as `reserved` (invisible) or `exists` (look-alike). The load of a name with no account says it before the app signs in (`taken: 'invisible'|'lookalike'`, beside `found: false`). A name is cut at its last whole character within 40 code units (`clean_`, `core.js` `nameCut`: a grapheme where the engine segments them, else a code point), so a name within the limit is unchanged. A name that is another Unicode form of an account's name (NFC, case aside) opens that account under its own spelling (`acct_`, load and save), and the load names that spelling (`name`) for the app to keep. Existing accounts are never renamed, merged or changed; the admin's Players page lists the existing pairs that look alike
