The self-update checks that the version it deployed is the one that answers (REE-342, the foundation phase's delivery trial, Pierre's issue of 2026-11-27: the updater reported a deploy without checking which build answers; any change to the release fallback, rollback or deployment policy stays his decision, and this changes none). After repointing the web app deployments, `autoUpdate` asks each one for a reply (a GET with no parameter, which reads nothing) and compares its `v` with the version deployed (`selfServeStart_`, `selfServeCheck_`). The result is the Script Property `AUTO_SERVE` (the version deployed, its Apps Script version, what each deployment answered, the version numbers they served before, and the last version seen serving), kept after a success as the last good version. Until the new version answers everywhere the deploy reads "NOT verified" in the Deploy log and every up-to-date run asks again (`selfServeRun_`: one request a deployment, never a new version, never a deployment change); the Deploy log says when it answers. An older version still answering 30 minutes after the deploy, or a reply that is not the script's JSON (a build that fails to load, whose own trigger runs may never come), writes one line a day to the Alerts tab and the Deploy log with what answers and the last good version. The check never repoints or rolls back a deployment: that stays a person's decision.
